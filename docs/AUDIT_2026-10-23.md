### H1. 기기 → Mac "이동"이 복사하지 않은 파일까지 지울 수 있음 (데이터 손실, 확인 + 추정)
- **2026-10-23 수정됨 (D61)** — 회귀 테스트 `TransferManagerTests`의 "Moves never delete what was not copied" 7개
- `TransferManager.swift:259-261`, `:519-521`, `deleteEntries` `:597-605`; `PBMTPBridge.c:430-437`
- 이동은 시작 전에 트리를 걷고, 끝나면 걸은 항목을 아래에서부터 지운 뒤 **폴더 자체에 DeleteObject**를 보낸다. Android MtpServer는 폴더를 재귀 삭제한다(추정 — 실기기 확인 필요).
  - 전송 중 그 폴더에 새로 생긴 파일(카메라 촬영, 다운로드)과 걷기에서 제외한 `.phonebridge-*` 항목이 복사 없이 삭제된다.
  - 게다가 `LIBMTP_Get_Files_And_Folders`는 메타데이터를 못 읽은 자식을 **조용히 건너뛰고**(libmtp.c:4636-4640) 오류 스택도 남기지 않는다. 브리지는 이를 `PB_STATUS_OK`로 돌려준다. 일시적 PTP 오류로 빠진 파일도 같은 식으로 지워진다.
- Mock의 `delete`는 비어 있지 않은 폴더를 거부하므로 테스트가 이 경로를 잡지 못한다.
- 수정: 폴더를 지우기 직전에 다시 나열해 비어 있을 때만 삭제(아니면 남기고 경고). 목록 조회는 `LIBMTP_Get_Children` + 핸들별 `Get_Filemetadata`로 바꿔 일부 실패를 "불완전 목록"으로 표시하고, 불완전 목록이면 원본 삭제를 거부.

### H2. Finder 브로커가 상대의 "자기 신고" 서명 식별자만 확인 (보안, 확인)
- **2026-10-23 수정됨 (D62)** — 회귀 테스트 `PeerRequirementTests` 4개, `FinderIntegrationTests`의 거부 시험 3개. 설치된 Developer ID 서명본으로 요구 조건 동작 확인
- `FinderBrokerServer.swift:143-161`

- 같은 사용자의 아무 프로세스나 `codesign -s - -i com.phonebridge.PhoneBridge.FinderVolume`로 서명하면 소켓(`group.com.phonebridge.shared/finder-broker.sock`)에 붙어 휴대폰 파일 목록·읽기, 쓰기 허용 시 생성·이름 변경·이동·삭제까지 할 수 있다. 쓰기 범위 검사(`MTPFileRepository.swift:252-259`)도 클라이언트가 보낸 `parentPath`를 그대로 믿는다.

### H3. Finder "대치" 중 30초 삭제 유예가 업로드 도중 만료 (데이터 손실, 확인)
- **2026-10-23 수정됨 (D63)** — 회귀 테스트 `FinderWriteTests` 3개
- `FinderWriteCoordinator.swift:159-166`(타이머), `:206-209`(`expire`), `:48-77`(`commit`)
- Finder 대치는 delete → 새 파일 복사 → close 시 commit 순서다. 타이머는 진행 중인 commit과 묶여 있지 않아, 업로드가 30초를 넘으면(실기기 20 MB/s 기준 약 0.5 GB 이상) 백업이 먼저 영구 삭제된다. 이후 업로드가 실패하면 `restorePendingDelete`가 복원할 것이 없다.
- 수정: 같은 키의 commit·rename·move가 대기·진행 중이면 유예를 연장(또는 만료를 commit 종료 시점으로 미룸).

### H4. 기기가 준 파일 이름을 Mac에 쓸 때 검사하지 않음 (보안, 확인)
- **2026-10-23 수정됨 (D64)** — 회귀 테스트 4개(`FileNameRulesTests` 2, `TransferManagerTests` 1, `BrokerTransferTests` 1)
- `LibMTPBackend.swift:250`, `DeviceFileSystem.swift:217-224` → `TransferManager.swift:242/268/548`, `DeviceDragExporter.swift:55/104`, `PreviewService.swift:50`
- `FileNameRules`에는 기기 방향(`sanitizedForDevice`)만 있다. 이름이 `..`, `../../x`, `a/b`인 객체를 보고하는 악의적·비정상 MTP 기기(리눅스 가젯 등)는 사용자가 고른 폴더 밖에 파일을 쓰게 하거나, `..` 폴더를 상위 폴더에 "병합"시키고 "모두 대치"로 덮어쓰게 할 수 있다. 샌드박스가 범위를 줄이지만, 사용자가 예전에 홈 폴더를 골랐다면 홈 전체가 대상이다.
- 수정: MTP 경계(`fileItem`)에서 `/`·NUL 치환, `""`/`.`/`..` → `_`, 255바이트 제한. 쓰기 직전에 최종 경로가 대상 폴더 아래인지 표준화 경로로 재확인.

### H5. 한 이동 작업이 자기가 방금 쓴 파일을 덮어쓰고 두 원본을 모두 지움 (데이터 손실, 확인)
- **2026-10-23 수정됨 (D61)** — 회귀 테스트 `TransferManagerTests`의 "Moves never delete what was not copied" 7개
- `TransferManager.swift:230-261`, `:271-294`
- 하위 폴더 검색 결과의 `DCIM/Camera/IMG_0001.JPG`와 `Pictures/Edited/IMG_0001.JPG`를 잘라내 Mac에 붙이면, 두 번째가 첫 번째 결과와 충돌한다. "대치"(또는 앞선 진짜 충돌의 "모두에 적용")를 고르면 첫 파일을 덮고 두 원본을 다 지운다.
- 대소문자·NFC/NFD만 다른 이름, 그리고 `LibMTPBackend.string()`이 앞뒤 공백을 잘라 같아진 이름(아래 L 항목)도 같은 경로를 탄다.
- 수정: 작업이 쓴 로컬 URL 집합을 두고, 거기와 충돌하면 항상 "둘 다 유지".

## 4. 확인 결과 문제없음
- C 브리지 메모리: 파일·저장소 목록, 오류 스택 해제, 오류 시 버퍼 이중 해제 없음, 진행률 콜백 수명, fd 소유권, 전역 libusb 상태 잠금 — 모두 정상. clang 분석기 경고 0건.
- 기기 문자열: libmtp가 UTF-16 → UTF-8 변환, `String(cString:)`은 잘못된 UTF-8을 고치므로 트랩 없음.
- IOKit: `IOObjectRelease` 균형, `Unmanaged` 자기 참조 해제, 콜백 큐 한정.
- IPC 프레임 길이 상한(헤더 4 MiB·본문 64 MiB) 확인 후 할당, 잘못된 JSON은 EPROTO 응답, 버퍼 이름 경로 탈출 차단, 감사 토큰 사용으로 pid 경쟁 없음.
- Entitlement 최소화: 임시 예외·library validation 해제·dyld 환경 변수 허용 없음. 앱·확장·헬퍼 모두 Hardened Runtime. 샌드박스 밖은 해제 헬퍼뿐.
- dylib: `@rpath` 설치 이름, 번들 내부 rpath만 사용, 복사 시 재서명 → dylib 하이재킹 경로 없음.
- 배포: install.sh는 sudo·xattr·spctl 변경 없이 서명·팀·공증을 검증. cask sha256 고정. 저장소에 비밀 값 없음.
- 현지화: 374개 키 ko/en 모두 번역, 형식 지정자 일치, 리터럴 호출 50곳 인자 수 일치.
- UI 코드에 강제 언래핑·범위 밖 인덱스 위험 없음.
